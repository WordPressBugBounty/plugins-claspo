== 🎯 The right popup for the right visitor ==

Set placement and display conditions without a developer:

* <strong>Audience</strong>: new or returning visitors, device, country, region and city
* <strong>Behavior</strong>: time on site or page, scroll depth, inactivity, exit intent, number of pageviews
* <strong>Context</strong>: page URL, traffic source, UTM parameters, cart activity
* <strong>Your own data</strong>: cookies, local storage, Data Layer values and JavaScript variables

With UTM targeting, a visitor from a specific email, social or paid campaign sees the popup made for that campaign, so discounts go to the moments that close a sale rather than to everyone.

<strong>WordPress targeting out of the box.</strong> The plugin hands Claspo what WordPress knows about the page and the visitor: the kind of page, its categories and tags, the WooCommerce product with its price and stock, the cart total, items and coupons, and whether the visitor is signed in. Use any of them as a display condition. Every group can be switched off on the plugin's Targeting data tab.

== 🧠 Qualify before you collect ==

An email is easy to get. Knowing who you are adding to the list is worth more. Ask a question or offer a choice before the contact form: a multi-step flow lowers friction and tells you what the visitor is interested in, how ready they are to buy and which incentive works. A teaser lets them reopen the offer after closing it.

== 🤫 Popups that do not annoy ==

* <strong>Silence interval</strong>: a gap between popups, 3 minutes by default, adjustable
* <strong>Overlap protection</strong>: two widgets never show at the same time, even with duplicated rules
* <strong>Frequency rules</strong>: how often a returning visitor sees the same campaign

== 🧪 A/B testing on autopilot ==

Compare offers, audiences, messages, triggers, layouts or game mechanics, not just button colors. Autopilot shifts traffic to the variant that performs better and keeps the test running. Analytics show views, conversions, target actions, device data, reward statistics and confidence scores, so you know which version is ahead and how sure the result is.

= How are pageviews calculated? =

A pageview is counted each time a page with the Claspo script loads.

If a visitor refreshes or revisits the page, it counts again.

We use pageviews, not impressions, because triggers are evaluated on every visit:

* time delays;
* scroll depth;
* exit intent;
* cart behavior.

Even if no popup is shown, the system processes the visit to decide whether it should appear.

= How does Claspo handle user data? =

This plugin uses the [Claspo](https://claspo.io) service to enable features such as popups for email capture, lead generation, notifications, and surveys. Claspo provides the platform for creating and managing these web widgets.

To understand how Claspo handles user data collected on your website, please refer to our [Data Processing Agreement](https://claspo.io/data-processing-agreement/), [Terms of Use](https://claspo.io/terms-of-use/), and [Privacy Policy](https://claspo.io/privacy-policy/).

= What does the plugin itself send to Claspo? =

Two things, and both are listed here so there are no surprises.

* To show the status of your widgets in wp-admin, the plugin asks script.claspo.io for the public configuration of your Script ID: once a day, when you open the plugin page or the dashboard, and when you click Check now. The request carries only the Script ID. No content, users or visitor data from your site are sent.
* With a targeting group switched on under Targeting data, the plugin hands the matching values to the Claspo script in the visitor's browser, so you can use them in display conditions: the kind of page and its categories, the name and price of the WooCommerce product being viewed, the cart total and item count, and whether the visitor is signed in. Product and cart groups appear only on sites with WooCommerce. Cart and sign-in values are fetched per visitor and never written into a cached page. Every group can be switched off.
